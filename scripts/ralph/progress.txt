## Codebase Patterns
- JSON output files use `{ _meta: { datapackVersion: '1.7.3+1.21.1', generatedAt: '...' }, data: [...] }` format. All readers must handle both the old array format and the new object format (check `Array.isArray`).
- `legendaries.json` is an EXCEPTION to the `{ _meta, data }` format — it uses `{ _meta, legendaries: [...], obtainMethods: {...}, dimensions: [...] }` because the UI imports it directly and reads named keys. Do NOT wrap in a `data` key.
- Legendary/mythical Pokémon are identified by `labels` array in species JSON (look for "legendary" or "mythical"); there are NO entries for legendaries in spawn_pool_world/.
- Species generation folders map to regions: generation1→kanto, generation2→johto, generation3→hoenn, generation4→sinnoh, generation5→unova, generation6→kalos, generation7/7b→alola, generation8→galar, generation8a→hisui, generation9→paldea.
- `seed-db.ts` calls extract-pokemon.ts, extract-spawns.ts, extract-items.ts via spawnSync before seeding — data always comes from the canonical datapack, not manually-edited files.
- DB tables (pokemon, spawn_entries, items, moves) have a `source_file TEXT` column for traceability.
- Extract scripts use COBBLEMON_DATAPACK_PATH env var (default: `./data/datapack`).
- `extract-moves.ts` fetches from PokeAPI — do NOT call from seed automatically (network may be unavailable; it has its own caching).
- TypeScript typecheck: `npm run typecheck` (tsc --noEmit). Uses strict mode with noUnusedLocals/Parameters.
- `esbuild` in node_modules may be platform-specific (macOS vs Linux); run `npm install --platform=linux --arch=arm64 esbuild` if needed in Linux container.
- Spawn conditions use `minSkyLight`/`maxSkyLight` (not `minLight`/`maxLight`) — matches raw datapack field names.
- `neededNearbyBlocks` in spawn files can be either `string[]` or `Array<{blocks: string[], range?: number}>` — always handle both formats.
- `spawn_entries` table has a `weight_multiplier TEXT` column (JSON) for conditional weight multipliers.
- `data/*.json` files are gitignored but exist on disk; only scripts and TypeScript source code are committed. gym-leaders.json, raids.json, shops.json, etc. are manually curated and not generated by extract scripts — they persist on the filesystem but are never committed.
- Recipe files in `recipe/` use 6 main types: crafting_shaped, crafting_shapeless, brewing_stand, cooking_pot_shapeless, smelting/blasting, stonecutting. Two subdirs: `recipe/brewing_stand/` and `recipe/campfire_pot/`. bag_items/ and held_items/ use .js files (JS scripts, not JSON) — only filenames are usable for item ID discovery.
- Species filenames in datapack use no hyphens: `mrmime.json` (not `mr-mime.json`). Validate species names against `data/datapack/data/cobblemon/species/**/*.json` filenames (strip .json extension).
- `loot_table/ruins/` contains `minecraft:archaeology` dig loot, NOT chest loot. `loot_table/sets/` has 8 generic reward categories. `loot_table/injection/` injects into vanilla Minecraft loot tables.
- Raid Dens, Gym Leaders, and Shop NPCs are all custom server content — no canonical datapack source. dialogues/ has only healer/example NPCs (Sacchi is a healer). loot_table/villages/ has only pokecenter chest loot.
- When using TypeScript `"prop" in obj` check and the type already guarantees the property exists, the truthy branch becomes `never` — use `=== undefined` instead.
- worldgen/structure/ has ruins (20+), fossils (24+), shipwreck_coves, fishing_boat structures — NO raid dens.
- shops.json is gitignored (data/*.json) — transform scripts run in-place on disk; only TypeScript source changes are committed.
- Standard Apricorn Balls use 4 Apricorns (DIFFERENT colors per ball) + metal ingot. NO Tumblestones. Tumblestones (Red/Sky/Black) are ONLY for Ancient Balls.
- BotanyPots and Adorn ARE integrated in the datapack (namespaces botanypots/, adorn/). Adorn adds apricorn furniture; BotanyPots enables automated crop growing of Berries and Apricorns.
- Shiny Charm and Macho Brace are NOT in the Cobblemon 1.7.3 datapack — mark as TODO if referenced in guides.
- EV yields are in species JSON under `evYield` key: e.g. `{'speed': 2}` for Jolteon. Always verify from datapack rather than relying on general Pokémon knowledge.
